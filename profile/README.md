<p>长期挂着的账号，出问题往往不是在某一天突然坏掉，而是在第二周、第三周的某个凌晨悄悄断了，等早上发现时已经离线六小时。这类事故几乎都能通过一套按天推进的开通流程避免：开通前把指标定成数字，开通当天验一遍，头三天跑基线，第一周放量，之后进入固定巡检节奏。下面按时间轴把每个节点该做什么列清楚，节点之间的间隔可以按自己的节奏压缩，但顺序不建议打乱。</p>

<h2>一、T-3 天：把需求写成能对账的数字</h2>
<h3>先算清三个数</h3>
<p>账号总数、同时在线数、单日活跃时长。这三个数决定了要买多少条出口、每条出口配几个环境、以及需要什么级别的带宽。很多人只报账号总数，结果买回来的条数按总数配，实际同时在线只有三分之一，钱花在了闲置线路上。</p>
<h3>再定两条红线</h3>
<p>一条是断线容忍时长，比如「单次断线不超过十分钟」；一条是验证容忍比例，比如「单周触发验证的账号不超过一成」。把这两条写进采购沟通记录里，后面判断线路是否合格就有依据，不用凭感觉。</p>

<h2>二、T-0：开通当天验四项</h2>
<img src="/tp.png" alt="开通当天四项连通性验收的检测结果面板">
<h3>四项逐条过</h3>
<p>第一项，连通性：从实际使用的机器上访问目标站点，能正常打开且不弹验证。第二项，出口身份：查 ASN、IP 类型、所属城市，与订单描述一致。第三项，稳定性：连续 ping 或 HTTP 探测一百次，记录超时次数与最大耗时。第四项，隔离性：确认这条出口没有被分给别的账号，问服务商要一份分配清单。</p>
<h3>当天不做放量</h3>
<p>开通当天只做验证，不加账号。原因很简单：新线路的头几小时可能还在收敛，此时压上全量账号，一旦出问题分不清是线路问题还是配置问题。用一条测试账号跑两小时，观察登录态是否稳定，是更稳的做法。</p>

<h2>三、T+1 到 T+3：跑通与抖动观察</h2>
<h3>建立基线日志</h3>
<p>这三天每天记录：出口地址变化次数、断连次数与时段、平均响应耗时、验证触发次数。三天数据足够看出规律，比如每天固定某个时段抖动，通常是上游链路在这个时间做维护或有流量高峰。</p>
<h3>识别「假稳定」</h3>
<p>有些线路白天很稳，凌晨两三点断一次，白天补不回来。判断方法是看断连的时间分布，如果集中在固定时段且每天重复，说明是链路特性而非偶发，要么和服务商确认维护窗口，要么给关键账号配一条备用出口做自动切换。</p>

<h2>四、T+4 到 T+7：放量到目标号数</h2>
<h3>每天加一批，每批留观察</h3>
<p>建议每天新增不超过总量的三成，新加的账号单独成组，观察二十四小时无异常再并入主组。并入时更新账号与出口的绑定表，把「新线观察中」的标记去掉，避免后面接手的人误判。</p>
<h3>环境与出口一一对齐</h3>
<p>放量阶段最容易漏的是环境创建。每加一个账号，先建独立配置文件，配好时区、语言、WebRTC，再绑出口，最后才登录。顺序颠倒的话，第一次登录就已经带着不匹配的指纹，后面再改也留下了记录。</p>

<h3>告警比人盯更重要</h3>
<p>凌晨断线靠人发现不现实。用一个每五分钟探测一次的小脚本，连续三次失败就推送到群里，比任何巡检表都及时。脚本本身不复杂，关键是有人负责接收并处理，否则告警会迅速变成噪音。</p>

<h3>月末怎么判断续费还是换</h3>
<p>把整月的断连次数、验证比例、平均响应耗时和月费放在一起看。如果断连和验证都在容忍线内，续费；如果某一项持续超标且服务商两次处理未改善，换。判断周期不要短于一个月，单周波动不足以说明问题。</p>
<h3>换线要留过渡期</h3>
<p>换供应商时新旧并行一周，新线跑通再停旧线。账号逐个迁移，不要一次性切换，迁移后观察三天再动下一个。这套流程看着慢，但能把迁移风险摊薄到几乎察觉不到。</p>

<h2>常见问答</h2>
<h3>长期挂着，需要每天重启客户端吗？</h3>
<p>答：不需要。频繁重启会让出口重新协商，反而增加地址变化的概率。建议每周固定一个低峰时段重启一次，其余时间保持常驻。如果客户端有内存泄漏导致越用越慢，那就每天低峰重启，但重启时间要固定。</p>
<h3>账号半夜掉线，第二天补登录有影响吗？</h3>
<p>答：短时间离线通常不影响，但连续多天在同一时段掉线会形成异常模式。处理重点是消除夜间断连，而不是白天加紧补登。给关键账号配自动切换的备用出口，是解决夜间断连最直接的办法。</p>
<h3>一条出口能挂几个长期在线的号？</h3>
<p>答：长期在线建议一号一线。若成本受限，两条线三个号是可接受的折中，但要保证同一站点上不同时在线。再多就会出现「谁在什么时候用了哪条线」说不清的情况，运维成本会超过省下的线路费。</p>
<h3>服务器和住宅 IP 怎么配合？</h3>
<p>答：服务器负责跑常驻任务和日志，住宅出口负责对外访问，两者分开。把业务直接跑在住宅线路上容易受本地断电、断网影响；把出口放在服务器上则要注意服务器本身的 IP 不能泄露，需要在服务器侧做出口绑定，避免真实地址外露。</p>
